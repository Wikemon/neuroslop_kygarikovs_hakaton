# Как устроен main.ipynb

[main.ipynb](main.ipynb) определяет, какие объявления закончились сделкой через Авито. Сделкой считаем продажу покупателю, который связался с продавцом через площадку. Ноутбук показывает, как данные об объявлении, действия покупателей и переписка превращаются в признаки модели.

Запустите **Run All** из корня проекта в окружении с зависимостями из [requirements.txt](requirements.txt). Анализ, очистка, признаки и разметка передаются между ячейками в таблицах pandas. В конце ноутбук записывает один файл — `submission.csv` в корне проекта.

## Что происходит в каждом разделе

| Раздел | Что делаем | Что смотреть в выводе |
|---|---|---|
| **1. Загрузка данных** | Читаем объявления, события, сообщения, опросы и проверенные ответы. Собираем список исходных `listing_id` для проверки итогового файла. | Размеры таблиц, количество уникальных объявлений и состав проверенной выборки. |
| **2. Анализ данных и поиск признаков** | Ищем пропуски, дубли и выбросы. Смотрим распределения и корреляции Спирмена. На проверенной выборке сравниваем цены, сроки размещения, ответы опросов, каналы связи и этапы переписки. | У каждого сигнала видны число наблюдений, число сделок и доля. В конце раздела таблица связывает находки с очисткой и будущими признаками. |
| **3. Очистка данных** | Удаляем точные дубли. При аномальной цене заменяем пропусками обе цены, при противоречивых датах — обе даты. Проверяем время событий и сообщений. Восстанавливаем категорию, если у карточек с тем же заголовком она одна. | Размеры таблиц до и после очистки, число заполненных категорий и сохранение всех ID объявлений. |
| **4. Расчёт признаков** | Считаем признаки карточки, опросов, событий, чатов и истории продавца. Добавляем сохранённые оценки текста чатов и собираем таблицу по `listing_id`. | Одна строка на объявление. Для ключевых сигналов из чатов снова показываем долю сделок, теперь по признакам, рассчитанным на очищенных сообщениях. |
| **5. Разметка** | Берём официальные метки из `verified.csv`. Для дополнительных меток повторяем действующий отбор кандидатов из переписки и исключаем все ID с официальными ответами. В текущем запуске в обучение идут 614 таких строк с весом 0,10. | Число меток по источникам и итоговый состав дополнительных меток. |
| **6. Обучение и проверка** | Объединяем вероятности двух логистических регрессий. Модель с дополнительными метками даёт 75% итоговой вероятности, модель на проверенных ответах — 25%. Порог подбираем внутри обучения по сумме баллов ТЗ. | F1, CatShareMAE и баллы за десять повторов кросс-валидации, ошибки по категориям и пример оценки для объявлений без ответа на опрос. |
| **7. Итоговый прогноз** | Подбираем итоговый порог, обучаем модели на доступных им метках и получаем прогноз для всех карточек. Заблокированным объявлениям ставим `is_deal = 0`. | В `submission.csv` есть `listing_id,is_deal`, все 15 274 уникальных ID и значения 0 или 1 без пропусков. |

Например, в разделе 2 проверяем, начал ли чат и открыл ли номер **один и тот же покупатель**. Среди проверенных объявлений с таким совпадением было 8 сделок из 8, а при двух каналах связи без совпадения покупателя — 57 из 159. Это наблюдение объясняет, зачем в разделе 4 считаем `buyers_with_chat_and_phone`. Восемь примеров дают основание для признака с ограниченным покрытием.

## Откуда взялись данные и расчёты

| Раздел | Файлы проекта | Что взяли |
|---|---|---|
| **1. Загрузка** | [listings.csv](data/listings.csv), [events.csv](data/events.csv), [messages.csv](data/messages.csv), [surveys.csv](data/surveys.csv), [verified.csv](data/verified.csv) | Пять исходных таблиц. `verified.csv` содержит 300 официальных ответов для обучения и проверки на отложенных фолдах. |
| **2. Анализ** | [analyzing_of_verified.ipynb](analysis/analyzing_of_verified.ipynb), [data_clearing.ipynb](analysis/data_clearing.ipynb), [feature_engineering.ipynb](feature/feature_engineering.ipynb) | Из этих ноутбуков взяли подход к проверке аномалий и сравнению карточек, опросов, событий и чатов. В `main.ipynb` таблицы анализа строятся заново по исходным данным. |
| **3. Очистка** | `analysis/data_clearing.ipynb` и раздел восстановления категорий в `feature/feature_engineering.ipynb` | Перенесли обработку дублей, цен и времени, а также заполнение категории по заголовку. |
| **4. Признаки** | `feature/feature_engineering.ipynb`, [chat_features.csv](feature/chat_features.csv) | Из ноутбука перенесли расчёт и объединение признаков. CSV содержит готовые оценки текста, полученные в [sentence_transformers.ipynb](feature/sentence_transformers.ipynb). |
| **5. Разметка** | [survey_deal_labels.ipynb](feature/survey_deal_labels.ipynb), [making_new_verified.ipynb](analysis/making_new_verified.ipynb), [new_verified.ipynb](analysis/new_verified.ipynb), [good_examples_of_verified_by_messages.csv](feature/good_examples_of_verified_by_messages.csv) | Перенесли логику отбора ответов «Продал на Авито» и сборки дополнительных меток. Список чатовых кандидатов читаем из готового CSV. |
| **6–7. Модель и прогноз** | [models/model.ipynb](models/model.ipynb) | Перенесли предобработку, обучение двух моделей, подбор порога и расчёт метрик. Прогноз сохраняем в `submission.csv` рядом с `main.ipynb`. |

[features.csv](data_by_dewallen/features.csv) и [extend_verified.csv](analysis/extend_verified.csv) служат для сверки с прежними расчётами. Для запуска `main.ipynb` нужны пять исходных CSV из `data/` и два готовых CSV из `feature/`. Сам `main.ipynb` считает признаки и собирает разметку в памяти.

## Результат проверки

В сохранённом прогоне на `verified.csv` средний **F1 — 0,8266**, **CatShareMAE — 2,94 п. п.**, **26,70 балла из 30** по формуле задания. CatShareMAE показывает, на сколько процентных пунктов в среднем предсказанная доля сделок отличается от проверенной по семи категориям. Под таблицей метрик есть разбор пропущенных и ложных сделок по категориям.
